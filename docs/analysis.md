# 파일을 묶고 폴더 이름을 정하는 과정

앱은 먼저 파일 사이의 관련도를 계산해 그룹을 만듭니다. 그다음 필요한 문서만 일부 읽어 소속을 다시 판단하고, 마지막에 각 그룹의 이름을 정합니다. 전체 순서는 [engine.py](../organizer/analysis/engine.py)에 있습니다. [앱 사용법](../README.md) · [기여 가이드](../CONTRIBUTING.md)

## 1. 파일명에서 주제와 회차 분리하기

예를 들어 `02-1. 패킷 분석 실습_최종(1).pdf`에서는 다음 값을 따로 남깁니다. ‘최종’이나 같은 순번이 여러 과목에 등장해도, 파일의 주제를 별도로 비교할 수 있습니다.

| 항목 | 추출한 값 |
| --- | --- |
| 정규화한 이름 | 패킷 분석 실습 |
| 순번과 역할 | `02-1`, 실습 |
| 버전 및 사본 표기 | 최종, (1) |
| 확장자 | pdf |

스캐너는 크기, 생성·수정 시각과 실제 저장 경로도 기록합니다. 다운로드는 최초 기본 선택이며 해제할 수 있습니다. 선택한 폴더 바로 아래의 파일만 분석하고 파일 식별자로 중복을 제거합니다. `chap.0`, `ch02`, `practice1` 같은 표기는 회차 단서입니다. 서로 다른 두 자료부터 `안개꽃_시안`, `안개꽃_견적`처럼 고유한 작업명이 반복되면 관련도에 반영합니다. ‘자료’, ‘여행’, ‘예약’ 같은 일반적인 역할 이름만으로 작업을 식별하지 않습니다. [scanner.py](../organizer/files/scanner.py) · [features.py](../organizer/analysis/features.py)

긴 난수형 이름은 부분 문자열로 비교하지 않습니다. 형식·길이·확장자·위치가 같고 기록된 다운로드 시각이 5분 이내면 일괄 다운로드를 제안할 수 있습니다. 다운로드 시각이 모두 없을 때는 같은 다운로드 사이트와 2분 이내의 파일 생성 시각을 함께 요구합니다.

## 2. 파일 쌍의 유사도 계산하기

| 단서 | 비교 방법 |
| --- | --- |
| 이름에 쓰인 단어 | 폴더의 파일명에서 TF-IDF 벡터를 만들고 코사인 유사도를 구합니다. 두 글자씩 잘랐을 때 겹치는 부분도 비교합니다. |
| 한·영 용어 문맥 | ‘Wireshark’와 ‘패킷’처럼 이름에 같은 글자가 없어도 사전에서 공유하는 문맥이 있으면 점수에 반영합니다. 사전에 없는 주제도 고유 단어가 반복되면 묶일 수 있습니다. |
| 시각·회차·위치·버전 | 이름 단서를 결합한 점수에 보조 근거로 반영합니다. 실제 상위 폴더를 비교하므로 서로 다른 원본 아래의 동명 폴더를 혼동하지 않습니다. 없는 시각은 일치로 취급하지 않습니다. 같은 날 받았거나 확장자가 같다는 사실만으로 같은 작업이라고 판단하지 않습니다. |
| 다운로드 출처 | 남아 있는 HTTPS 페이지 경로와 쿼리는 약한 단서입니다. 학교 학습관리시스템(LMS)에서 확인한 강좌 식별자는 같은 사이트 안에서 비교하며, 같은 강좌와 다른 강좌를 구별하는 데 사용합니다. 출처가 없는 기존 파일도 나머지 단서로 분석합니다. |

LMS 첨부 주소의 불투명한 키는 같은 엔드포인트에서 서로 다른 키 두 개 이상이 각각 여러 게시물에 반복될 때 강좌 출처의 단서로 채택합니다. 파일에 명시된 학년도가 다르면 관련도를 낮추고, 참고문헌의 발행 연도는 학년도와 구분합니다. 점수는 0.00~1.00의 대칭 행렬로 표현하며 대각선은 1.00입니다. [terms.json](../organizer/analysis/terms.json) · [similarity.py](../organizer/analysis/similarity.py) · [course_source.py](../organizer/analysis/course_source.py) · [matrix.py](../organizer/analysis/matrix.py)

## 3. 추천 그룹과 신뢰도 정하기

**완전 연결 응집형 계층 클러스터링**으로 후보 그룹을 만듭니다. 두 그룹 사이에서 가장 덜 닮은 파일 쌍의 유사도가 병합 기준에 도달하면 합칩니다. 기본 병합 기준은 0.60이며, 최소 신뢰도를 낮추면 최대 0.50까지 완화합니다. 의미 사전만 겹치는 두 파일은 추가 근거가 필요합니다. 두 작업에 모두 관련된 파일 하나가 양쪽 자료 전체를 잇는 현상을 줄이는 방식입니다. 같은 프로젝트라도 이름과 출처가 부족하면 미분류에 남을 수 있습니다. 다른 프로젝트명이나 연도 충돌은 본문 분석 뒤에도 유지합니다. 모든 파일 쌍을 비교하므로 메모리와 비교량은 파일 수의 제곱에 비례합니다. 한 번에 분석하는 파일은 모든 원본을 합쳐 최대 3,000개입니다. [클러스터링](../organizer/analysis/clustering.py) · [측정 결과](search.md#측정-결과)

파일 자신을 제외한 그룹 평균과 가까운 이웃 최대 세 개의 평균으로 적합도를 구합니다. 1·2위 그룹의 점수 차이와 그룹 내부의 유사도를 함께 반영한 **신뢰도**는 추천 근거를 비교하기 위한 점수입니다. 실제 정답률을 추정하려면 별도 검증이 필요합니다.

| 1차 판단 | 기준과 후속 처리 |
| --- | --- |
| 높음 | 최초 그룹과 1위 그룹이 일치하고 적합도가 병합 기준 이상, 차점과 차이 ≥ 0.10, 신뢰도가 사용자의 최소 기준(기본 0.7) 이상이면 추천합니다. 차점도 0.60 이상이면 0.25 이상 차이가 나야 합니다. |
| 중간 | 후보 그룹이 있고 적합도가 0.23 이상이거나, 이름 단어가 없는 지원 문서에서 기준 파일과 같은 습득 경로가 확인되면 본문 분석 후보가 됩니다. 같은 폴더에서 수정 시각이 48시간 이내이거나 다운로드 도메인과 세부 경로가 같은 경우가 해당합니다. |
| 낮음 | 근거가 부족한 파일은 미분류에 둡니다. 비교할 기준 그룹이 없으면 소속을 위한 본문 분석도 생략합니다. |

두 파일의 관련성은 이웃 추천과 후보 비교에 활용합니다. 새 폴더를 추천하려면 이동할 수 있는 고유 파일이 3개 이상이어야 합니다. 크기가 같으면 SHA-256으로 실제 내용을 비교하고, 사본은 대표 경로 하나만 자동 이동 후보로 남깁니다. 기존 폴더는 한 파일도 받을 수 있습니다. [관련도 판정](../organizer/analysis/confidence.py) · [고유 파일 판정](../organizer/analysis/eligibility.py)

## 4. 애매한 파일의 소속 다시 보기

**애매한 파일만 본문 분석**을 켜면 중간 등급 중 지원 형식의 파일 앞부분을 확인합니다. 최종 발췌량은 파일당 최대 2,400자입니다.

| 형식 | 읽는 부분 |
| --- | --- |
| PDF | 메타데이터 제목과 첫 페이지의 텍스트. 이미지로만 된 페이지의 OCR은 지원 범위 밖입니다. |
| DOCX, PPTX, XLSX, HWPX | 제목 메타데이터와 문서 앞부분, 슬라이드·시트·첫 섹션의 일부 XML을 읽습니다. |
| TXT, MD, CSV, TSV, LOG | 앞부분 최대 8 KiB를 읽습니다. |
| HWP, ZIP 등 본문 리더가 없는 형식 | 이름과 메타데이터로 관련도를 계산합니다. |

발췌한 단어가 영향을 주는 행과 열만 갱신합니다. 파일명에 이미 주제 단어가 있으면 본문으로 소속을 바꾸기 전에 해당 파일 쌍의 1차 점수가 0.50 이상인지 확인합니다. `첨부.pdf`처럼 주제 단어가 없는 이름은 본문에서 주제를 찾을 수 있습니다. 다시 판단할 때는 1차에서 안정적으로 남은 그룹을 기준으로 삼아, 애매한 파일들이 서로를 근거로 연쇄 편입되는 일을 막습니다. **유사도 행렬**의 셀에서 1차 점수와 최종 점수를 비교할 수 있습니다. 새 문서 형식의 발췌 함수는 `readers.py`의 `READERS`에 등록합니다. [readers.py](../organizer/analysis/readers.py) · [refinement.py](../organizer/analysis/refinement.py)

## 5. 그룹 이름 정하기

1. 사용자가 지정한 그룹 이름과 같은 LMS 강좌에서 확인한 과목명을 먼저 적용합니다.
2. 출처 페이지에서 확인한 강좌명이나 제목에 명시된 과목명 항목을 찾습니다.
3. **문서 표지로 그룹 이름 찾기**가 켜져 있으면 지원되는 강의 자료의 OT·수업개요·강의계획서에서 대표 PDF 또는 PPTX 한 개를 고릅니다. 이런 자료가 없으면 1주 1차시 PPTX를 찾습니다. PDF는 첫 페이지, PPTX는 발표 순서상 첫 슬라이드를 사용합니다.
4. 파일명에서 주차 앞에 반복되는 수업 이름, 붙임·회차·양식을 걷어낸 행사 이름, 팀명·기수·프로젝트 표기를 살핍니다. 이어서 모든 파일에 반복된 구절을 원래 표기대로 찾습니다. 단서가 부족하면 임시 이름을 붙이고, 강좌 출처나 이름 후보가 충돌하면 확인을 요청합니다.

사용자는 그룹 이름을 직접 변경할 수 있습니다. 강좌 출처가 확인되면 같은 강좌에서 확인한 이름을 재사용하고, 출처가 불분명하면 현재 그룹에 저장합니다. 그룹 이름 변경은 원본 파일 이름을 바꾸지 않습니다. 표지 확인과 소속 판정을 위한 본문 분석은 각각 켜고 끌 수 있습니다. [candidates.py](../organizer/analysis/candidates.py) · [course_titles.py](../organizer/analysis/course_titles.py)

## 편집 내용과 이동 기록

앱은 `%LOCALAPPDATA%\MoaFileReview`에 다음 데이터를 저장합니다.

| 항목 | 기록하는 내용 |
| --- | --- |
| `feedback.sqlite3` | 수동 소속, 같은 그룹·다른 그룹 관계, 확정한 이름, 연결한 사이트, 브라우저 다운로드 출처 |
| `History/` | 실제로 이동한 파일의 원래 경로, 목적지, 복원 상태 |
| `download-settings.json` | 선택한 폴더, 최소 신뢰도, 기존 폴더 활용 방식, 선택적 본문 분석, 표지 확인 설정 |

소속과 관계 편집은 SQLite 트랜잭션으로 저장해 다음 분석에서도 우선 적용합니다. 같은 그룹 관계는 이어서 적용하고, 다른 그룹 관계와 충돌하는 편집은 저장 전에 멈춥니다. 수동 결정 뒤에도 측정한 유사도를 볼 수 있습니다. 같은 볼륨에서는 파일 ID와 생성 시각을 이용해 이름 변경이나 이동을 추적합니다. 복사본이나 다른 볼륨으로 옮긴 파일은 새 파일로 인식될 수 있습니다. [feedback.py](../organizer/files/feedback.py) · [storage.py](../organizer/files/storage.py)

브라우저 확장은 페이지 제목과 쿼리·조각을 뺀 페이지 주소, 확인 가능한 강좌명을 로컬 수신기에 전달합니다. 파일과 출처를 특정하기 어려우면 연결을 보류합니다. 앱 창을 닫아도 수신기가 기록한 내용은 다음 분석 때 반영합니다. [브라우저 연결 방법](usage.md#브라우저에서-다운로드-출처-기록하기) · [browser_bridge.py](../organizer/browser/browser_bridge.py) · [capture_host.py](../organizer/browser/capture_host.py)

**최근 정리**에서 작업별 원본·목적지·처리 상태를 확인하고 원하는 작업을 복원합니다. 미리보기와 실행 시점에 원래 경로 점유와 목적지 파일의 내용을 확인합니다. 이동 중 오류나 종료로 새 폴더의 고유 파일이 3개 미만이면 이력으로 복원을 시도합니다. 충돌이 남으면 원인을 기록하고, 재시도할 때 남은 이동만 처리합니다. 생성 당시 식별자가 일치하는 빈 폴더만 정리합니다. [이동과 복원](../organizer/files/storage.py)

최근 정리 이력은 실제 `History/` 기록을 읽습니다. 설치 전 파일의 사용 이력이나 열람 시각을 만들어내지 않습니다. 파일 관계 보기는 선택한 파일 주변 최대 다섯 개의 단서를 보여주며, 사용자가 다른 묶음으로 지정한 관계는 제외합니다.

번들에 포함된 외부 구성 요소의 라이선스도 저장소에서 확인할 수 있습니다. [pypdf](../vendor/pypdf-LICENSE.txt) · [Pretendard](../desktop/assets/Pretendard-LICENSE.txt) · [Phosphor](../desktop/assets/Phosphor-LICENSE.txt)
