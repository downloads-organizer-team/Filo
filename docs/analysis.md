# 파일을 묶고 폴더 이름을 정하는 과정

앱은 먼저 파일 사이의 관련도를 계산해 그룹을 만듭니다. 그다음 필요한 문서만 일부 읽어 소속을 다시 판단하고, 마지막에 각 그룹의 이름을 정합니다. 전체 순서는 [engine.py](../engine.py)에 있습니다. [앱 사용법](../README.md) · [기여 가이드](../CONTRIBUTING.md)

## 1. 파일명에서 주제와 회차 분리하기

예를 들어 `02-1. 패킷 분석 실습_최종(1).pdf`에서는 다음 값을 따로 남깁니다. ‘최종’이나 같은 순번이 여러 과목에 등장해도, 파일의 주제를 별도로 비교할 수 있습니다.

| 항목 | 추출한 값 |
| --- | --- |
| 정규화한 이름 | 패킷 분석 실습 |
| 순번과 역할 | `02-1`, 실습 |
| 버전 및 사본 표기 | 최종, (1) |
| 확장자 | pdf |

스캐너는 크기, 생성·수정 시각, 폴더 안의 상대 위치도 기록합니다. `chap.0`, `ch02`, `practice1` 같은 표기는 회차 단서로 씁니다. 서로 다른 세 자료에 `제주여행_항공권`처럼 같은 작업명이 반복되고 구분자 뒤의 항목이 다르면 해당 작업명을 관련도에 반영합니다. [scanner.py](../scanner.py) · [features.py](../features.py)

## 2. 파일 쌍의 유사도 계산하기

| 단서 | 비교 방법 |
| --- | --- |
| 이름에 쓰인 단어 | 폴더의 파일명에서 TF-IDF 벡터를 만들고 코사인 유사도를 구합니다. 두 글자씩 잘랐을 때 겹치는 부분도 비교합니다. |
| 한·영 용어 문맥 | ‘Wireshark’와 ‘패킷’처럼 이름에 같은 글자가 없어도 사전에서 공유하는 문맥이 있으면 점수에 반영합니다. 사전에 없는 주제도 고유 단어가 반복되면 묶일 수 있습니다. |
| 시각·회차·위치·버전 | 위의 이름 단서를 결합한 점수에 보조 근거로 반영합니다. 같은 날 받았거나 확장자가 같다는 사실만으로 같은 과목이라고 판단하기는 어렵습니다. |
| 다운로드 출처 | 같은 HTTPS 페이지 경로는 약한 단서입니다. 학교 학습관리시스템(LMS)에서 확인한 강좌 식별자는 같은 사이트 안에서 비교하며, 같은 강좌와 다른 강좌를 구별하는 데 사용합니다. |

LMS 첨부 주소의 불투명한 키는 같은 엔드포인트에서 서로 다른 키 두 개 이상이 각각 여러 게시물에 반복될 때 강좌 출처의 단서로 채택합니다. 파일에 명시된 학년도가 다르면 관련도를 낮추고, 참고문헌의 발행 연도는 학년도와 구분합니다. 점수는 0.00~1.00의 대칭 행렬로 표현하며 대각선은 1.00입니다. [terms.json](../terms.json) · [similarity.py](../similarity.py) · [course_source.py](../course_source.py) · [matrix.py](../matrix.py)

## 3. 추천 그룹과 신뢰도 정하기

**완전 연결 응집형 계층 클러스터링**으로 후보 그룹을 만듭니다. 두 그룹 사이에서 가장 덜 닮은 파일 쌍의 유사도가 0.60 이상일 때 병합합니다. 두 과목과 모두 닮은 공동 과제 하나가 양쪽 자료 전체를 잇는 현상을 줄이는 방식입니다. 과목 안에서도 이름이 크게 다른 자료는 미분류에 남을 수 있습니다. 모든 파일 쌍을 비교하므로 메모리와 비교량은 파일 수의 제곱에 비례합니다. 한 번에 분석하는 파일은 최대 3,000개입니다. [clustering.py](../clustering.py) · [완전 연결 정의](https://docs.scipy.org/doc/scipy/reference/generated/scipy.cluster.hierarchy.linkage.html)

파일 자신을 제외한 그룹 평균과 가까운 이웃 최대 세 개의 평균으로 적합도를 구합니다. 1·2위 그룹의 점수 차이와 그룹 내부의 유사도를 함께 반영한 **신뢰도**는 추천 근거를 비교하기 위한 점수입니다. 실제 정답률을 추정하려면 별도 검증이 필요합니다.

| 1차 판단 | 기준과 후속 처리 |
| --- | --- |
| 높음 | 최초 그룹과 1위 그룹이 일치하고 적합도 ≥ 0.60, 차점과 차이 ≥ 0.10, 신뢰도 ≥ 0.62이면 추천합니다. 차점도 0.60 이상이면 0.25 이상 차이가 나야 합니다. |
| 중간 | 후보 그룹이 있고 적합도가 0.23 이상이거나, 이름 단어가 없는 지원 문서에서 기준 파일과 같은 습득 경로가 확인되면 본문 분석 후보가 됩니다. 같은 폴더에서 수정 시각이 48시간 이내이거나 다운로드 도메인과 세부 경로가 같은 경우가 해당합니다. |
| 낮음 | 근거가 부족한 파일은 미분류에 둡니다. 비교할 기준 그룹이 없으면 소속을 위한 본문 분석도 생략합니다. |

자동 그룹은 기본 두 파일 이상입니다. 사용자가 확정한 단일 파일 그룹과 ‘다른 그룹’ 관계로 분리된 일부 단일 기준 파일은 유지할 수 있습니다. [confidence.py](../confidence.py) · [constraints.py](../constraints.py)

## 4. 애매한 파일의 소속 다시 보기

**애매한 파일만 본문 분석**을 켜면 중간 등급 중 지원 형식의 파일 앞부분을 확인합니다. 최종 발췌량은 파일당 최대 2,400자입니다.

| 형식 | 읽는 부분 |
| --- | --- |
| PDF | 메타데이터 제목과 첫 페이지의 텍스트. 이미지로만 된 페이지의 OCR은 지원 범위 밖입니다. |
| DOCX, PPTX, XLSX, HWPX | 제목 메타데이터와 문서 앞부분, 슬라이드·시트·첫 섹션의 일부 XML을 읽습니다. |
| TXT, MD, CSV, TSV, LOG | 앞부분 최대 8 KiB를 읽습니다. |
| HWP, ZIP 등 본문 리더가 없는 형식 | 이름과 메타데이터로 관련도를 계산합니다. |

발췌한 단어가 영향을 주는 행과 열만 갱신합니다. 다시 판단할 때는 1차에서 안정적으로 남은 그룹을 기준으로 삼아, 애매한 파일들이 서로를 근거로 연쇄 편입되는 일을 막습니다. **유사도 행렬**의 셀에서 1차 점수와 최종 점수를 비교할 수 있습니다. 새 문서 형식의 발췌 함수는 `readers.py`의 `READERS`에 등록합니다. [readers.py](../readers.py) · [refinement.py](../refinement.py)

## 5. 그룹 이름 정하기

1. 사용자가 지정한 그룹 이름과 같은 LMS 강좌에서 확인한 과목명을 먼저 적용합니다.
2. 출처 페이지에서 확인한 강좌명이나 제목에 명시된 과목명 항목을 찾습니다.
3. **강의 표지로 과목명 찾기**가 켜져 있으면 OT·수업개요·강의계획서에서 대표 PDF 또는 PPTX 한 개를 고릅니다. 이런 자료가 없으면 1주 1차시 PPTX를 찾습니다. PDF는 첫 페이지, PPTX는 발표 순서상 첫 슬라이드를 사용합니다.
4. 파일명에서 주차 앞에 반복되는 수업 이름도 살핍니다. 단서가 부족하면 임시 이름을 붙이고, 강좌 출처나 이름 후보가 충돌하면 확인을 요청합니다.

그룹 화면의 **파일명 변경**에서 과목명을 확정할 수 있습니다. 강좌 출처가 확인되면 같은 강좌에서 이름을 재사용하고, 출처가 불분명하면 현재 그룹에 저장합니다. 표지 확인과 소속 판정을 위한 본문 분석은 각각 켜고 끌 수 있습니다. [candidates.py](../candidates.py) · [course_titles.py](../course_titles.py)

## 편집 내용과 이동 기록

앱은 `%LOCALAPPDATA%\MoaFileReview`에 다음 데이터를 저장합니다.

| 항목 | 기록하는 내용 |
| --- | --- |
| `feedback.sqlite3` | 수동 소속, 같은 그룹·다른 그룹 관계, 확정한 이름, 연결한 사이트, 브라우저 다운로드 출처 |
| `History/` | 실제로 이동한 파일의 원래 경로, 목적지, 복원 상태 |
| `download-settings.json` | 하위 폴더 포함, 선택적 본문 분석, 강의 표지 확인 설정 |

소속과 관계 편집은 SQLite 트랜잭션으로 저장해 다음 분석에서도 우선 적용합니다. 같은 그룹 관계는 이어서 적용하고, 다른 그룹 관계와 충돌하는 편집은 저장 전에 멈춥니다. 수동 결정 뒤에도 측정한 유사도를 볼 수 있습니다. 같은 볼륨에서는 파일 ID와 생성 시각을 이용해 이름 변경이나 이동을 추적합니다. 복사본이나 다른 볼륨으로 옮긴 파일은 새 파일로 인식될 수 있습니다. [feedback.py](../feedback.py) · [storage.py](../storage.py)

브라우저 확장은 페이지 제목과 쿼리·조각을 뺀 페이지 주소, 확인 가능한 강좌명을 로컬 수신기에 전달합니다. 파일과 출처를 특정하기 어려우면 연결을 보류합니다. 앱 창을 닫아도 수신기가 기록한 내용은 다음 분석 때 반영합니다. [브라우저 연결 방법](../README.md#브라우저에서-다운로드-출처-기록하기) · [browser_bridge.py](../browser_bridge.py) · [capture_host.py](../capture_host.py)

**최근 이동 되돌리기**는 최근 이동 기록에서 파일을 찾아 원래 위치로 복원합니다. 원래 경로가 이미 사용 중이거나 이동 뒤 파일 내용이 달라졌으면 복원을 보류하고 사유를 표시합니다. 이번 이동이 만든 그룹 폴더는 비어 있을 때 정리합니다. [storage.py](../storage.py)

번들에 포함된 외부 구성 요소의 라이선스도 저장소에서 확인할 수 있습니다. [pypdf](../vendor/pypdf-LICENSE.txt) · [Pretendard](../desktop/assets/Pretendard-LICENSE.txt) · [Phosphor](../desktop/assets/Phosphor-LICENSE.txt)
